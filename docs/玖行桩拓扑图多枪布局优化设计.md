# 玖行桩模拟插件 · 拓扑图多枪布局优化设计

> 文档类型：问题分析 + 需求说明 + 改版方案  
> 文档版本：**v0.2**（对齐 OpenSpec change `jx-topology-layout-list-view`）  
> 适用版本：玖行协议 V2.24 拓扑画布（`JxMainView.vue`）  
> 关联截图：`docs/assets/jx-topology-*.png`  
> 实施清单：`openspec/changes/jx-topology-layout-list-view/tasks.md`

---

## 1. 问题现象

### 1.1 正常场景（≤2 枪 / 桩）

- 每桩下方 A/B 枪水平并列，车辆轮廓、枪号标签、连线间距充足。
- 桩 ID、费率图标、链接状态在桩体左侧，不与邻桩枪位冲突。
- 总线 → 垂线 → 桩 → 分线 → 枪 → 车的层级关系清晰。

### 1.2 异常场景（≥3 枪 / 桩，尤其 4 枪）

| 现象 | 说明 |
|------|------|
| **枪位横向侵入邻桩列** | 4 枪时枪簇总宽约 436px，远超单列分配宽度，B/C/D 枪与右侧桩的 A 枪叠在一起 |
| **车辆轮廓重影** | 多辆虚线/实线车 SVG 在同一水平带叠加，无法辨认归属 |
| **枪号标签不可读** | 「B枪」「A枪」等文字层叠 |
| **分线/总线错位** | `jx-car-bus-line` 按本桩枪簇宽度绘制，但物理绘制区域已越过列边界 |
| **左侧信息区受压** | `jx-pile-left-info` 绝对定位在桩中心偏左，邻桩枪簇扩张后与之争抢空间 |

---

## 2. 根因分析

### 2.1 布局模型矛盾（核心）

当前实现采用 **「桩列等分 + 枪簇自适应撑宽」** 的双层网格：

```
协议根节点
    │
════╪═════ 总线（jx-bus-line，跨全列）
    │   │   │
  桩1  桩2  桩3   ← jx-topology：gridTemplateColumns = repeat(N, minmax(92px, 1fr))
    │   │   │
  枪区 枪区 枪区   ← jx-car-strip：与上层 **相同** 列定义
 A B  A B  ABCD   ← jx-gun-list：width: fit-content，按枪数撑开
```

- **列宽由桩数量决定**（`minmax(92px, 1fr)`，容器 `max-width: 1020px`）。
- **内容宽由枪数量决定**（单枪节点 `--jx-gun-node-width: 100px`，间距 `12px`）。

当 `枪簇宽度 > 列宽` 时，flex 子项不会换行到下一行，而是 **溢出到相邻 grid 单元**，造成视觉重叠。overflow 未裁剪，故问题直接暴露。

### 2.2 量化估算

| 枪数 | 枪簇宽度（约） | 4 桩时每列宽度（1020px 容器） | 是否溢出 |
|------|----------------|-------------------------------|----------|
| 2 | 212px | ~255px | 否 |
| 3 | 324px | ~255px | **是** |
| 4 | 436px | ~255px | **严重** |

3 桩 × 4 枪时，每列约 340px，4 枪仍可能贴边；**任意邻桩存在 2 枪 + 4 枪组合时，4 枪桩必侵入 2 枪桩列**（与用户截图一致）。

### 2.3 次要因素

1. **桩层与枪层列定义强绑定**：无法让「枪多的桩」单独占更宽列。
2. **枪只支持单行横排**：`jx-gun-list { flex-direction: row }`，无折行策略。
3. **固定枪节点宽度 100px**：未随枪数缩放。
4. **画布最大宽度 1020px**：多桩 + 多枪组合下信息密度超限。
5. **绝对定位的桩侧信息**：不参与列宽计算，易被邻列内容覆盖。

### 2.4 问题归类

| 类型 | 描述 |
|------|------|
| P0 | 多枪横向溢出导致枪/车/标签不可辨认 |
| P1 | 连线语义断裂（看不清枪属于哪台桩） |
| P2 | 桩 ID / 费率 / 链接图标与枪区争抢空间 |
| P3 | 4 桩 × 4 枪时整图信息密度过高，即使不重叠也偏拥挤 |

---

## 3. 设计目标

1. **1～4 枪 / 桩** 均可读，**1～N 桩** 可扩展（建议 N≤8 为舒适区）。
2. 保持现有语义：**协议 → 桩 → 枪 → 车** 拓扑关系不被破坏。
3. 不牺牲关键交互：点桩开侧栏、点车连 VIN / 启动控制、充电 HUD、费率气泡。
4. 改动优先 **CSS / 网格策略**，避免引入重型图引擎（G6 等）除非后续有缩放、拖拽强需求。
5. 与宿主深色主题、现有 `--jx-*` 令牌一致。

---

## 4. 方案对比

### 方案 A：动态列宽 + 横向滚动（推荐 · 改动小）

**思路**：每桩列宽 = `f(枪数)`，不再与邻桩均分 `1fr`；整板超出视口时横向滚动。

```
gridTemplateColumns: 每桩 max(枪数) 推导宽度，例如：
  2枪 → 220px
  3枪 → 320px
  4枪 → 440px
```

| 优点 | 缺点 |
|------|------|
| 保留现有视觉语言，学习成本低 | 桩数多时需横滑 |
| 实现量小，主要改 `topologyColumns` 计算与 `overflow-x: auto` | 总线需随内容宽度延伸 |
| 彻底消除列间侵入 | 超宽时协议根节点居中感变弱（可固定根节点居中、内容区滚动） |

**增强**：枪数 ≥3 时枪节点宽由 100px 缩至 80px，进一步压缩。

---

### 方案 B：枪位双行网格（2×2）（推荐 · 与 A 组合）

**思路**：单桩枪数 >2 时，枪列表改为 **2 列 × 2 行**（最多 4 枪），列宽上限约 220px。

```
     桩
     │
   ┌─┴─┐
  A枪 B枪
  C枪 D枪
```

| 优点 | 缺点 |
|------|------|
| 列宽可控，与 2 枪桩对齐 | 垂向高度增加 |
| 4 枪仍保持紧凑 | 分线拓扑需改为「桩下短总线 + 两行分支」 |
| 与方案 A 叠加后效果最佳 | 仅适用于 ≤4 枪（当前产品上限，可接受） |

---

### 方案 C：桩卡片纵向堆叠（左右分栏）

**思路**：画布分左右两区：

- **左（窄，~240px）**：桩列表卡片（ID、在线状态、费率、枪数摘要），纵向滚动。
- **右（宽）**：选中桩的 **枪位详图**（大图、车辆、HUD、操作入口）。

```
┌──────────┬─────────────────────────────┐
│ 桩列表    │  选中桩：0317864…           │
│ ○ 桩1 2枪 │      [桩图标]               │
│ ● 桩2 4枪 │   A枪  B枪                  │
│ ○ 桩3 2枪 │   C枪  D枪                  │
│ ○ 桩4 4枪 │   [车][车][车][车]          │
└──────────┴─────────────────────────────┘
```

| 优点 | 缺点 |
|------|------|
| 多桩多枪永不重叠 | **失去「一屏看全站」拓扑感** |
| 右侧枪区可做得很大 | 交互路径变长（需先选桩） |
| 适合运维监控向 UI | 改造量中等，需新选中态与右侧布局 |

**适用**：桩数经常 >4 或需同时监控大量 HUD 时。

---

### 方案 D：可缩放 / 平移画布（Pan & Zoom）

**思路**：保留现有排版，外层加 `transform: scale()` + 拖拽平移；默认缩放使全图纳入视口。

| 优点 | 缺点 |
|------|------|
| 不改节点排布逻辑 | **不解决重叠**，仅缩小后更难点击 |
| 适合未来 G6 迁移 | 实现与触控体验成本高 |

**结论**：仅作辅助手段，**不能单独作为 P0 修复**。

---

### 方案 E：折叠枪（3～4 枪收起到「+N」）

**思路**：默认只显示前 2 枪，其余收入「展开」；或 hover 桩时扇形展开。

| 优点 | 缺点 |
|------|------|
| 列宽恒定 | 隐藏枪位，违背「拓扑全览」诉求 |
| | 充电中枪可能被折叠，体验差 |

**结论**：不推荐作为主方案，可作极端密度下的可选模式。

---

## 5. 推荐组合方案（实施优先级）

### 5.1 一期（P0 修复，建议优先）

**A + B + 横向滚动 + 溢出保护**

1. `topologyColumns` 改为按每桩枪数计算像素宽度（或 `minmax` 下限随枪数上升）。
2. 枪数 ≥3 时 `jx-gun-list` 使用 `grid-template-columns: repeat(2, 1fr)` 双行布局。
3. `jx-board` 增加 `overflow-x: auto`，`jx-topology` / `jx-car-strip` 使用 `width: max-content; min-width: 100%`。
4. `jx-car-slot` 增加 `overflow: visible` → 改为列内 `overflow: hidden` 仅作兜底，并以列宽正确化为根本手段。
5. 枪数 ≥3 时 `--jx-gun-node-width: 80px`。
6. 桩左侧信息改为 **桩列内相对定位**（`left: 0` 相对 `jx-pile-col`），避免与邻列重叠。

**预期效果**：与用户截图同场景下，4 枪桩呈 2×2，列宽约 180～220px，4 桩总宽约 900～1000px，无重叠；超出时横滑。

### 5.2 二期（列表视图 + 切换）— 本变更正式纳入

1. **拓扑 / 列表双视图切换**（方案 C）：工具栏分段控件，两视图 `v-show` 互斥、状态共享。
2. **列表视图布局**：左桩卡片轨（~260px）+ 右枪位详区；详见 **§12**。
3. **密度提示**（可选 P2）：枪数 ≥3 且拓扑模式时，顶部提示「紧凑布局」。
4. **连线优化**：双行枪位时，分线采用「桩下短竖线 → 横总线 → 每枪竖线」经典电工拓扑样式（见示意图）。

### 5.3 三期（长期）

- 若桩数 >6 成为常态，评估迁移 AntV G6 或自研可缩放拓扑（设计文档 §2.2 原规划）。

## 8. 响应式策略

| 视口宽度 | 策略 |
|----------|------|
| ≥1280px | 双行枪位 + 动态列宽，尽量无横滑 |
| 1024～1279px | 启用横滑；枪节点 80px |
| <1024px | 建议提示切换「列表视图」（二期）或强制横滑 |

## 9. 验收标准

### 9.1 拓扑模式

- [ ] 4 桩 × 4 枪：任意两桩枪位 **bounding box 不相交**（像素级抽检）。
- [ ] 3 桩 × 4 枪 + 1 桩 × 2 枪混合：无标签叠字。
- [ ] 单桩 1～4 枪：连线正确指向对应车辆。
- [ ] 横滑后添加桩、选中桩、点车交互正常。
- [ ] 充电 HUD、VIN 气泡不被邻列裁剪（`overflow` 策略验证）。
- [ ] 主题浅/深色下布局不破。

### 9.2 列表模式

- [ ] 工具栏可切换「拓扑 ↔ 列表」，刷新后保留上次选择（localStorage）。
- [ ] 4 枪桩在右详区 2×2 展示，无重叠。
- [ ] 左栏选中桩与 `activePileId`、侧栏四 Tab 联动。
- [ ] 点车、VIN、启动控制/充电信息、HUD 与拓扑行为一致。
- [ ] 列表模式下侧栏贴右，不随桩索引漂移。
- [ ] 添加桩、筛选、折叠提示与拓扑规则一致。

## 11. 结论

多枪重叠 **不是渲染 bug**，而是 **网格列宽模型与枪簇内容宽度不匹配** 的结构问题。  

**一期（P0）**：方案 A + B（动态列宽、双行枪位、横向滚动），保留拓扑语义并消除重叠。  

**二期（本变更）**：方案 C 列表视图 + 工具栏切换，兼顾「全站拓扑一览」与「单桩枪位运维」。

## 12. 列表视图与拓扑切换（完整需求）

### 12.1 目标用户场景

- 同一场站 **4 桩 × 4 枪**，拓扑横滑仍嫌拥挤时，切换列表逐桩操作。
- 充电运维需看清 **HUD、枪状态、车辆** 时，右详区空间大于拓扑单列。
- 新手更习惯「先选设备、再看枪位」的列表心智。

### 12.2 切换控件

| 项 | 要求 |
|----|------|
| 位置 | `jx-toolbar`，导入/导出按钮左侧 |
| 形式 | `el-segmented` 或 radio-button：**拓扑** \| **列表** |
| 默认 | 拓扑；无 localStorage 记录时同 |
| 持久化 | `jx-board-view-mode`：`topology` \| `list` |

切换时 **不清空** `activePileId`；两视图共用 `visiblePiles` 筛选。

### 12.3 列表视图布局

```
┌─────────────────────────────────────────────────────────────┐
│ [拓扑 | 列表]  ← 工具栏                                      │
├──────────────┬──────────────────────────────────────────────┤
│ 桩列表       │ 枪位详区                                      │
│ (~260px)     │                                              │
│ ┌──────────┐ │ 桩头：ID · 在线 · TCP · ¥ · 链接            │
│ │● 桩1 4枪 │ │ ┌────┬────┐                                  │
│ └──────────┘ │ │ A  │ B  │  枪标签 + 状态 + 车 + HUD        │
│ ┌──────────┐ │ ├────┼────┤                                  │
│ │○ 桩2 2枪 │ │ │ C  │ D  │                                  │
│ └──────────┘ │ └────┴────┘                                  │
│ [+ 添加桩]   │                                              │
└──────────────┴──────────────────────────────────────────────┘
                    ↓ 选中桩
              ┌─────────────────┐
              │ jx-panel 侧栏    │  ← 固定贴右（非列比例定位）
              │ 基本|控制|订单|日志│
              └─────────────────┘
```

### 12.4 左栏桩卡片字段

| 字段 | 说明 |
|------|------|
| 桩号 | 主标题，`pile.pileId` |
| 状态点 | 离线灰 / 在线绿 / 故障黄 |
| 枪数徽章 | `N枪` |
| 摘要 | 可选：「M 枪充电中」 |
| 选中态 | teal 左边框或背景高亮 |

**交互**：单击 → `setActivePile` + 打开侧栏；双击离线桩 → 登录流程（同拓扑）。

### 12.5 右栏详区

- 不重复侧栏全部表单；仅 **桩头一行摘要** + **枪位网格**（推荐抽取 `JxGunCluster`）。
- 3～4 枪：**2×2 grid**；1～2 枪：单行。
- 复用：`handleCarClick`、`openStartControlDialog`、充电 HUD、`vinEdit` 气泡等。

### 12.6 侧栏定位差异

| 模式 | `jx-panel` 水平定位 |
|------|---------------------|
| 拓扑 | `drawerLeftStyle` 按桩列索引比例 |
| 列表 | `right: 12px` 固定（class `jx-panel--list-mode`） |

侧栏内容与四 Tab **不改动**。

### 12.7 与拓扑模式互斥显示

- `jx-board-topology`：`boardViewMode === 'topology'`
- `jx-board-list`：`boardViewMode === 'list'`
- 使用 `v-show` 保留 DOM，避免 HUD 定时器与选中态丢失。

### 12.8 空状态

| 条件 | 展示 |
|------|------|
| 无桩 | 左栏引导添加；右栏占位 |
| 有桩未选 | 默认选中 `visiblePiles[0]` 或提示选择 |
| 筛选隐藏 | 与拓扑相同「已折叠 N 个桩」 |

### 12.9 非目标（列表视图）

- 不在列表右栏复制「桩控制 / 日志」全文。
- 不在列表模式绘制协议总线拓扑线。
- 不强制窄屏自动切列表（仅建议，不自动）。
